# Viewer

Every adopted-list `bcl` call ensures its per-list viewer, except a new list created by rollover: its viewer stays deferred until `bcl start` begins Collect. It starts or restarts `serve.py --data <live-file>` on an available loopback port and records port, pid, plugin version, live data path, report path, base directory, scripts directory, and started-at in the per-repo file `$BCL_STATE_DIR/viewers/<owner>--<repo>.json`. A viewer is reused only when all paths match the current list; an owned viewer for the same live file is restarted when its worktree or report changes. The viewer always serves the live file, not a stale in-repo snapshot.

The live page footer shows `reading <path>, viewer <version>, started <IST>` only when the viewer is live. Default `render.py` output stays deterministic and has no footer. Times on the page are IST; never leave visible ISO timestamps in the user view.

The page polls with `HEAD` and reloads only when the ETag or fingerprint changes. That interval is a change check, not a full-reload timer. Local-file views still require a manual refresh. Lane status is derived at render from the job receipt: a live job shows its phase, a dead unfinished one `Interrupted · resume at <phase>`, and a fix or review lane with no job `Paused · needs resume`. `bcl pause --reason "why"` pauses the round and refuses new jobs until `bcl resume`; repeats are no-ops. Stale shows only for a live job with no heartbeat or progress past the stale limit.

Each repo has one viewer port, chosen once and saved as `viewer_port` on its registry records: a repo with no saved port takes the port in its own per-repo viewer file (registry repair; old per-list files never decide or veto it; they only steer a fresh pick while their viewer runs), else a deterministic slot from its repo id in 50000-59999, skipping ports another repo has saved or recorded and ports already in use. Adoption, or the first viewer start for a record without one, saves it. Port lookup stops with an error when one repo has two different saved ports or its recovered port is saved by another repo. A viewer still running from an old per-list file is stopped on upgrade and the repo moves once to its own port; re-bookmark that address. Every later list for the repo, rollover, restart and plugin upgrade reuses that port and serves the newest list, so one bookmark per repo always works. If the saved port is occupied by anything other than the repo's own viewer, `bcl` stops with an error and never picks another port. Never move or kill another list's viewer. A rollover does not retarget the viewer; `bcl start` on the new list performs that list's first viewer start on the same port.

Recovery, if `bcl` cannot start the viewer: from the skill directory, `python3 scripts/serve.py --data /absolute/path/findings.json --port <the repo's saved viewer_port>`. Without `--inventory`, each request discovers installed plugin manifests and uses the current time. `--inventory /absolute/path/inventory.json` supplies an inventory override. For one-off renders, `render.py --live` discovers installs and uses the current time, while `--now <ISO-8601>` injects a deterministic render time.
